# 安全维护检查清单

此检查清单有助于维护 GitHub Actions 工作流程和整体项目安全的安全标准。

## 月度安全任务

### GitHub Actions 安全
- [ ] 审查和更新固定的 action 版本
- [ ] 检查所使用 actions 中的新安全漏洞
- [ ] 验证所有 actions 仍在使用特定版本固定（无 `@main` 或 `@latest`）
- [ ] 审查工作流程权限并确保最小权限
- [ ] 测试安全工作流程功能

### 依赖安全
- [ ] 审查 npm audit 结果
- [ ] 更新带有安全补丁的依赖项
- [ ] 审查 Snyk 漏洞报告
- [ ] 检查影响项目依赖项的新 CVE

### 容器安全
- [ ] 审查 Trivy 扫描结果
- [ ] 将基础镜像更新到最新安全版本
- [ ] 扫描新的容器漏洞
- [ ] 审查 Dockerfile 安全最佳实践

## 周度安全任务

### 密钥管理
- [ ] 审查 Gitleaks 扫描结果
- [ ] 检查 TruffleHog 发现
- [ ] 审计存储库密钥并删除未使用的密钥
- [ ] 验证没有密钥提交到代码中

### 代码安全
- [ ] 审查 CodeQL 分析结果
- [ ] 检查 Semgrep 安全发现
- [ ] 解决代码中的任何新安全问题
- [ ] 审查拉取请求安全扫描

## 日常安全任务

### 监控
- [ ] 检查 GitHub 安全选项卡的新警报
- [ ] 审查安全工作流程运行结果
- [ ] 监控 Slack 通知的安全失败
- [ ] 验证定期安全扫描正在运行

## Action 版本更新流程

### 更新前
1. [ ] 检查 action 的变更日志以了解重大更改
2. [ ] 审查 action 的安全公告
3. [ ] 首先在功能分支中测试
4. [ ] 如果可能，验证 action 源代码

### 更新期间
1. [ ] 更新到特定版本（不是最新版本）
2. [ ] 更新 action 的所有实例
3. [ ] 测试工作流程功能
4. [ ] 在提交消息中记录更改

### 更新后
1. [ ] 监控工作流程运行是否有问题
2. [ ] 验证安全扫描仍然正常工作
3. [ ] 如需要更新文档

## 安全事件响应

### 如果安全扫描失败
1. [ ] 调查具体失败原因
2. [ ] 确定是否为误报
3. [ ] 如果是真实漏洞，创建问题进行跟踪
4. [ ] 修复漏洞或更新配置
5. [ ] 重新运行安全扫描以验证修复
6. [ ] 记录经验教训

### 如果检测到密钥
1. [ ] **立即**轮换暴露的密钥
2. [ ] 如需要从 git 历史中删除密钥
3. [ ] 审计密钥的使用位置
4. [ ] 更新密钥管理实践
5. [ ] 通知相关团队成员
6. [ ] 记录事件以防止未来发生

- [ ] 审计密钥使用和访问
